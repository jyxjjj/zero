# 网络安全与客户端接入

[用户规则索引](AGENTS.md)

这个工程做客户端。服务端由用户维护，下面的服务端配置已由用户确认强制执行。

## 指定依赖

| 依赖 | 固定版本 | 用途与版本依据 |
| --- | --- | --- |
| OpenSSL | 4.0.2 | TLS 后端；[发布记录](https://github.com/openssl/openssl/releases/tag/openssl-4.0.2) |
| curl/libcurl | 8.22.0 | HTTP 客户端，使用上述 OpenSSL 后端；[发布记录](https://github.com/curl/curl/releases/tag/curl-8_22_0) |
| nghttp2 | 1.70.0 | 为 libcurl 提供 HTTP/2 支持；[发布记录](https://github.com/nghttp2/nghttp2/releases/tag/v1.70.0)、[curl 依赖说明](https://curl.se/docs/libs.html) |

用户指定的这三个版本免源码审查，但版本、构建和协议协商必须检查。其他新增依赖另行确认。

使用项目专用的 libcurl 构建。选定 UE 版本后，要检查引擎自带库的版本和构建兼容性。

## 协议约束

| 项目 | 强制要求 |
| --- | --- |
| 网络应用数据传输 | TLS 1.3 |
| TLS 密钥交换组 | X25519MLKEM768 |
| TLS 1.3 密码套件 | TLS_AES_256_GCM_SHA384 |
| HTTP | HTTPS 上的 HTTP/2 |
| 对称加密 | AES-256-GCM |
| 0-RTT / Early Data | 必须显式禁用，绝对禁止发送与接受 |
| Session Ticket | 绝对禁止签发、保存与使用；收到对端票据直接丢弃 |

对端不支持就连接失败，TLS 版本、密钥交换组、密码套件和 HTTP 版本都不能降级。客户端、服务端、游戏同步、HTTP 请求和所有其他网络应用数据都必须遵守，后续版本也一样，不能为了性能或兼容性打开禁用功能。

每条新 TLS 连接都必须完整握手；票据不能缓存、持久化或用于会话恢复。

TLS_AES_256_GCM_SHA384 指定 TLS 1.3 使用 AES-256-GCM 加密和 SHA-384 哈希，密钥交换组另设为 X25519MLKEM768。nonce 管理和认证标签校验交给成熟库处理。

## 服务端条件

客户端只控制自己的行为，不能替服务端设置参数。

| 服务端配置 | 客户端怎么处理 |
| --- | --- |
| ssl_prefer_server_ciphers on | 仅提供规定的密码套件，并验证协商结果 |
| ssl_early_data off | 客户端遵守上述 Early Data 禁令 |
| ssl_session_timeout 10m | 服务端会话参数有效期为 10 分钟，不作为客户端请求超时或连接寿命 |
| ssl_session_cache shared:SSL:10m | 服务端维护名为 SSL 的 10 MiB 共享缓存，不转换为客户端缓存配置 |
| ssl_session_tickets off | 客户端遵守上述票据禁令 |

服务端开了会话缓存、设了超时，也不代表客户端能使用票据。[Nginx SSL 模块文档](https://nginx.org/en/docs/http/ngx_http_ssl_module.html)

## 客户端 HTTPS 配置

| 配置项 | 目标值 |
| --- | --- |
| CURLOPT_SSLVERSION | CURL_SSLVERSION_TLSv1_3 与 CURL_SSLVERSION_MAX_TLSv1_3 按位或 |
| CURLOPT_TLS13_CIPHERS | TLS_AES_256_GCM_SHA384 |
| CURLOPT_SSL_EC_CURVES | X25519MLKEM768 |
| CURLOPT_HTTP_VERSION | CURL_HTTP_VERSION_2_PRIOR_KNOWLEDGE |

每个配置调用都要检查返回结果。只允许 HTTPS，检查证书链和主机名，通过 ALPN 协商 HTTP/2。连接池只能复用满足全部安全要求的连接，重定向、代理和域名解析也要按同样要求处理。

发应用数据前，必须检查实际协商出的 TLS 版本、密码套件、密钥交换组和 h2。缺少 ALPN 或结果不符就拒绝发送。只提供 h2 还不够，也要确认实际协商为 h2；请求结束才检查，拦不住已经发出的数据。

配置依据为 curl 8.22.0 的对应文档：[TLS 版本](https://github.com/curl/curl/blob/curl-8_22_0/docs/libcurl/opts/CURLOPT_SSLVERSION.md)、[密码套件](https://github.com/curl/curl/blob/curl-8_22_0/docs/libcurl/opts/CURLOPT_TLS13_CIPHERS.md)、[交换组](https://github.com/curl/curl/blob/curl-8_22_0/docs/libcurl/opts/CURLOPT_SSL_EC_CURVES.md)、[HTTP 版本](https://github.com/curl/curl/blob/curl-8_22_0/docs/libcurl/opts/CURLOPT_HTTP_VERSION.md)。

## 全部通路

HTTP 走专用 libcurl，其配置只管经过该库的连接。非 HTTP 游戏数据也必须满足同样的协议要求，传输层要结合实时同步一起测试。

TLS 1.3 记录层需要可靠、有序的数据流，不能直接给普通 UDP 数据报套一层加密。游戏同步若用数据报，就要重新设计可靠传输，或由用户决定改协议。HTTPS 配置不会自动管到默认网络驱动。[TLS 1.3 规范](https://www.rfc-editor.org/rfc/rfc8446.html#section-1)

## 验收

- 构建与运行时均核对指定版本、OpenSSL 后端和 HTTP/2 能力。
- 正确配置的端点可协商 TLS 1.3、X25519MLKEM768、TLS_AES_256_GCM_SHA384 与 h2。
- TLS 1.2、其他交换组、其他密码套件、HTTP/1.1、HTTP/3、缺少 ALPN 和无效证书均被拒绝。
- 在拒绝降级的场景中，确认应用请求内容未发送。
- 确认客户端不发送 Early Data，完整握手及连接验证完成前不得传输应用数据；联调时检查服务端的拒绝行为。
- 客户端收到票据后不得缓存、持久化或用于后续连接。联调要检查服务端是否签发 Session Ticket，不能只看配置名称。
- 断开后重连必须执行完整握手；检查连接池和第三方通路均遵守 0-RTT 与 Session Ticket 禁令。
- 检查游戏同步、域名解析、代理、重定向和第三方功能的实际流量，不能绕过统一通路。
