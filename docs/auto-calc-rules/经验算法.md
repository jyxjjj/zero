# 角色等级经验算法

[自动计算与平衡规则索引](AGENTS.md)

版本：1。

## 适用范围

角色从 1 级、级内经验 0 开始。算法计算每级升级所需经验，等级在数学上没有上限。宠物经验曲线另定；宠物、召唤物和仆从的成长见[三套系统规则](../user-rules/characters/宠物召唤仆从.md)。

## 当级经验

当前等级为正整数 L，从 L 升至 L+1 所需经验为：

`E(L) = L² × (L + 100) = L³ + 100L²`

所有经验取整数，公式本身不需要舍入。当前级内经验达到 E(L) 即可升级，超出部分保留并继续用于下一等级。

低等级主要受二次项影响，高等级逐渐由三次项主导。相邻升级需求之差为 `3L² + 203L + 101`，始终为正，跨阶段没有跳变。

## 累计经验

到达等级 L 所需总经验不包含 L 升至 L+1 的消耗。令 n = L−1：

`T(L) = Σ E(k)，k = 1…L−1`

`T(L) = 100 × n(n+1)(2n+1) / 6 + [n(n+1)/2]²`

因此 T(1)=0，T(100)=57337500，T(2000)=4262467700000。恒等式 `T(L+1) − T(L) = E(L)` 用于验证累计结果。

## 时间模型

常规成长按每天有效获取经验 H=3 小时、180 天约等于 6 个月计算。有效时间只算实际产生经验的游戏时间。

100 级前每小时经验基准：

`R₀ = T(100) / (180 × 3) = 106180.555555… 经验/小时`

当前等级的预计经验效率：

`R(L) = R₀ × max(1, L/100)²`

100 级后，效率按等级平方增长，模拟高级内容的经验产出。怪物、任务、组队和实力差距增减益的奖励按这个基准设计，不会自动按小时给角色发经验。

当级预计有效小时：

`h(L) = E(L) / R(L)`

当级预计日历天：

`d(L) = h(L) / 3`

到达等级 L 的累计预计天数：

- L≤100：`D(L) = 180 × T(L) / T(100)`。
- L>100：`D(L) = 180 × [T(100) + 10000 × (L−100)(L+299)/2] / T(100)`。

上式在 100 级连续，D(100)=180 天。累计小时为 3D(L)。更改每日有效时间而维持经验效率时，日历时间按反比变化。

按这个基准，2000 级约要 188 年，体现极难达到的目标。特殊任务、全局提升、经验道具、异常高效率和运气能改变实际成长，死亡掉级会增加投入。演示表不算这些情况，也不把经验换成现实付款条件。模型还没用可玩内容测试，后续按实际经验产出调整。

## 独立实现

`level_experience_required(level, &experience)` 计算 E(L)，使用标准 C 整数运算，不依赖引擎对象或外部包。输出指针须指向有效的 `uint64_t` 变量。头文件使用纯 C 声明；后续 C++ 调用方须在包含该头文件时使用 `extern "C"` 指定 C 链接。

- `LEVEL_EXPERIENCE_SUCCESS`：计算成功并写入经验值。
- `LEVEL_EXPERIENCE_INVALID_LEVEL`：输入等级为 0。
- `LEVEL_EXPERIENCE_OVERFLOW`：结果超出 64 位无符号整数表示范围。
- 失败时保持输出参数原值；调用方必须检查返回值。
- 先检查加法和乘法范围，之后执行计算。

使用 64 位无符号整数时，能精确计算到 L=2642212。更高等级必须换用更大范围的数值表示，玩法等级仍无上限。溢出返回错误，不能封顶、回绕或返回低级兜底值。

C 函数只算每级经验需求。经验发放、升级循环、死亡后级内经验结算和保存由后续角色代码处理；累计经验和时间表按上面的公式计算。
